# HELIX / The Sorting Works

A standalone Three.js + TypeScript + Vite screening-floor experiment. This directory is independent of the Helix website. No changes were made to existing Helix projects.

Live site: https://projects.jessenth.com/Helix-Viz/

GitHub Actions runs tests, builds, and deploys to GitHub Pages on every push to main.

## Run

Requires Node.js 22 or later.

```powershell
npm install
npm run dev
```

Open the Local URL printed by Vite. For a specific port on Windows:

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5174
```

`npm run build` creates `dist/`. `npm test` runs six tests covering replay totals, pause/reset, fixed-clock partitioning, unresolved gates, invalid input, ranking timing, and a 26-survivor run. Serve `dist/` over HTTP; opening its HTML with `file://` does not support module loading.

The public repository does not contain complete saved Stage 3 investigations. Its README says investigation results live in the ignored `.stage3-results.json`. No complete Hardy Road result was available.

The included fixture was generated by running the original `stage3.run()` with explicitly mocked property, jurisdiction, and compliance inputs. The original building-fit function, benchmark cost registry, cost arithmetic, gate decisions, conditions, and ranking logic ran unchanged. No renderer code invents business outcomes.

## What is illustrative

The property is a fictional 6,000 sq ft retail shell with 14 ft height, $6,500 monthly base rent, a $900,000 budget, and no declared reserve. Compliance responses are deliberately synthetic: tutoring has an illustrative blocked preflight; other categories have conditional verification responses. These responses are not actual research or legal advice. Property-evidence source strings are labeled synthetic. Published opening-cost benchmarks are real registry data applied to this fictional scenario, not actual quotes for a property.

The fixture produces 15 building stops, two affordability stops, one compliance stop, and eight survivors. The conditional shortlist is veterinary, martial arts, then fitness. No cached neighborhood decision is provided, so neighborhood demand is unavailable for every category and does not distinguish candidates.

To regenerate using a read-only clone of the inspected repository:

```powershell
python scripts/create_fixture.py "<checkout>/project helix/stage3_engine/vendor"
```

## Mapping to the engine

1. All gate results already exist in the data. Animation presents the first stopping gate in the order building → affordability → compliance. The Python engine calculates all three even for candidates stopped earlier.
2. Both `fail` and `unknown` stop a cartridge. Unknown is preserved separately in counters and evidence. Conditional pass statuses continue with a yellow marker, including `pass_with_checks`, low-case affordability, reserve thresholds, and `pass_needs_verification`.
3. The affordability instrument shows base opening cost / capital. It is a physical comparison, not a new gate calculation. Missing reserve is never silently assumed to be zero for the gate.
4. Survivors wait in a buffer until screening finishes. Dispatch uses the engine's saved `shortlist` and `also_passed` order. It does not recalculate a score. The source ranking is lexicographic: fit confidence, base-case affordability, calibrated demand, cash headroom, condition count; exact ties retain registry order. The original tie-break explanations are inspectable.
5. A fixed 60 Hz simulation tick drives every pose, scan, and gate. Rendering cannot change an outcome. Play, pause, speed, timeline scrubbing, stepping, and restart operate on the simulation clock.

## Controls

- Play/pause, restart, step to the next entry/gate/sort event, speed, and timeline.
- Space toggles playback. Right arrow steps. Drag to orbit; scroll to zoom.
- Click a physical cartridge or its register row for results, inputs, sources, reasons, and raw gate evidence.
- Follow a selected cartridge; Reset view releases the camera.
- Click a gantry, its rule in the inspection desk, or the sorting assembly for the rule explanation.
- Filter the register to shortlist, stopped, or passing candidates. Shortlist rows follow ranking order.
- About the data shows provenance, exports the current JSON, and loads a complete 26-category `stage3.v1` result locally. Uploaded data stays in browser memory. Inconsistent gates, unsupported statuses, and incomplete rankings are refused.

## Structure and limits

- `src/adapter.ts`: preserves and validates source results; extracts recorded ranking.
- `src/simulation.ts`: fixed clock and deterministic physical poses.
- `src/scene.ts`: custom Three.js machinery, ray picking, lighting, shadows, camera, resource disposal; shared box geometry and materials.
- `src/main.ts` and `src/style.css`: inspection desk and controls.
- `public/fixture.json`: full annotated engine fixture.

Mechanical geometry and choreography are illustrative. They are not a physics solver. Soft shadows, capped pixel density, and shared geometry keep rendering bounded; ambient occlusion is not enabled. Google Fonts are an optional typography enhancement, with system fallbacks. This prototype replays results; it does not run Python in the browser or validate the truth of imported evidence.
